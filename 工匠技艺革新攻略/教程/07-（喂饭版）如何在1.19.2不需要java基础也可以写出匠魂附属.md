## 前言

很多人对模组的理解有一个误区，认为必须要极高的水平才能去写模组。实际上对于附属而言并不需要多高的代码水平

本篇教程更偏向于照顾没有基础的，想要尝试写匠魂附属的新人，进行喂饭式教学

本篇会拿部分附属中的代码来进行示例（例如ETSHtinker，已经过原作者授权）

**如果你写附属只是为了好玩，并不打算发布**可以无视接下来的前言内容

以下是我的一些个人建议（你头铁就是你对）

1源码应在github上公开，方便其他人参阅和整合包作者排查错误

2材料命名应尽可能地避免敏感和引人不适的话题

3文件和变量命名应尽可能地和实际内容相关，易于自己和他人理解

4材料描述应尽可能地描述通透，而不是一句话草草盖过，描述是给玩家看的，不是留你装x自嗨的

5版本号不要乱填，并且最好标注上对应的匠魂版本（比如1.19后几个版本有远古工具更新）

6基于某些前置（如部分魔法模组）进行开发的时候要谨慎，并且标注上对应的版本

7避免滥用自己还未完全理解的部分，出了错误容易卡很久

### 注册表，创造模式物品栏和物品注册

在主目录下先注册一个名为**Register**的软件包，并且在其中新建一个你**模组名+tab**的类（其实想起什么名字都可以，不一定要和我命名一样，但是不要起一些自己记不住，和毫不相干的名字）

创建完之后在类内写下这段，这是一个创造物品栏的相关字段（记得把tinkersclamp换成你的modid，后面不再提示）

```
public static final CreativeModeTab MATERIALS = new CreativeModeTab("tinkersclamp.materials") {    @Override    public ItemStack makeIcon() {        return null;    }};
```

这样我们就完成了一个创造模式物品栏的创建

"tinkersclamp.materials"为我们的本地化键名，后面**语言文件**的时候会进行解释

此时我们还没有物品，所以makeicon（）部分的返回值暂时写null，等下就补

然后我们在Register软件包下再新建一个名为ModID+Item的类，用于我们物品的注册

在这个类内这样写

```
public static final DeferredRegister<Item> ITEMS = DeferredRegister.create(ForgeRegistries.ITEMS, MODID);
```

如果你直接复制爆红了不必担心，鼠标悬浮看见"导入类"导入即可

导入静态常量的时候如果有多个选项记得选择需要的那个（比如我们这里MODID导入要选择我们自己的MODID

在这行之后我们

```
public static final RegistryObject<Item> cruse_ingot = ITEMS.register("cruse_ingot", () -> new Item(new Item.Properties().tab(TinkersClampTab.MATERIALS)));
```

就完成了一个名为"curse_ingot"的物品的注册，并且将其添加到了我们前面新建的创造模式物品栏当中

几个要注意的地方

NameSpace部分（命名空间，即RegistryObject<Item> curse_ingot这部分的"curse_ingot",不是字符串内的那个）在同一个类内不可以重名，它是一种标识符，在引用的时候会用上

后面那个字符串部分(绿色的""内部的部分)为物品的ID，会影响本地化键命名和配方添加等

如果注册多个物品只需要照着这个格式往下写即可

## 匠魂词条的注册

也是难得终于进入匠魂部分了

在**Register**软件包下新建一个名为**MODID+Modifier**的注册表

在类中写上

```
public static ModifierDeferredRegister MODIFIERS = ModifierDeferredRegister.create(MOD_ID);
```

然后在主目录下新建一个软件包，用于存放匠魂词条

在这个新的软件包下新建一个类，命名为你的词条的类名

里面这样写

```
//extend继承匠魂的Modifier类,不是反射里面的Modifier类,别搞错了//implement后面跟上匠魂的接口,这里用近战伤害的Hook做演示public class Rude extends Modifier implements MeleeDamageModifierHook {    public Rude(){}    //注册Hook标识符    //这步是必须,不然接口衍生的方法体无效    @Override    protected void registerHooks(ModuleHookMap.@NotNull Builder hookBuilder) {        //注册implement后根接口对应的ModifierHook标识符;        hookBuilder.addHook(this,ModifierHooks.MELEE_DAMAGE);    }    //MeleeDamage方法修改工具伤害    @Override    public float getMeleeDamage(IToolStackView tool, ModifierEntry modifier, ToolAttackContext context, float baseDamage, float damage) {        //将实体形参context.getLivingTarget()定义为名为enemy的一个LivingEntity，此步骤可以省略但是如果省略后面enemy要换为context.getLivingTarget()，实际应用的时候也可以直接模式变量更省事一些        LivingEntity enemy=context.getLivingTarget();        //检测该实体最大生命值是否为20点        if(enemy!=null&&enemy.getMaxHealth()==20){            //是，则输出原伤害+996            return damage+996;        }        //否则输出这个原伤害        return damage;    }}
```

此处拿词条Rude作为演示，996是为了测试的时候更明显一些

具体的每句作用已经在注释说明

之后我们回到刚才匠魂词条注册表类下面

```
public static ModifierDeferredRegister MODIFIERS = ModifierDeferredRegister.create(MODID);public static final StaticModifier<Rude> rude = MODIFIERS.register("rude", Rude::new);
```

这样就将这个词条加到这个表当中了
