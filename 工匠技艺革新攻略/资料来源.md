# 工匠：技艺革新 · 资料来源（怎么查证 CTI 的东西）

> 建立于 2026-10-13。本文件记录本次攻略会话用到的**权威数据源**，以及"某个配方是不是被 CTI 魔改过"该怎么查。
> 凡是涉及具体配方/数值的结论，都应先在这里选一个源查证，不要凭印象回答。

## 1. 官方中文维基（GitBook）

- 入口：<https://technological.gitbook.io/cti/>
- **全站索引（最重要）**：<https://technological.gitbook.io/cti/llms.txt> —— 列出每一页的标题+链接+slug；任何页面 URL 后面加 `.md` 就得到 Markdown 原文，便于直接抓取。
  - 例：`/cti/cai-liao-lie-biao/tertiary_materials/mo-gu-kuang.md`（蘑菇矿）
- 内容分布：材料列表（一~四级材料）、匠魂工具/盔甲/强化、更新日志（**只有 0.35~0.35d**）、FQA、外部教程。
- 局限：**材料页大多是空页或只有一张截图**（蘑菇矿、叶绿、幽灵都是空的），所以"某材料怎么获得"往往查不到，需要下面的第 2 条。
- GitHub 镜像：<https://github.com/dreamforSh/CTIwiki>（内容与线上一致，`git clone --depth 1` 后直接 `grep` 更快）

## 2. 整合包本体配置（判断"是否魔改"的唯一可靠途径）

- 服务端包仓库：**`dreamforSh/CTI-server`**（<https://github.com/dreamforSh/CTI-server>，约 527 MB，clone 用 `--depth 1`）
  - `mods/` —— 整合包实际使用的模组 jar（含自制模组 `cti-1.2.2.jar`、`etshtinker-*.jar` 等）
  - `config/ftbquests/quests/chapters/*.snbt` —— **任务书全文**（FTB Quests 原始 SNBT，含每条任务的标题/副标题/描述/奖励）
  - `kubejs/` —— CTI 的魔改脚本与数据包：
    - `server_scripts/*.js` —— 新增/替换的机器配方（`thermal.js`、`create.js` …）
    - `data/**` —— 数据包覆盖；文件名即配方 id，例如 `kubejs/data/tinkers_thinking/recipes/chlorophyte.json` 就是 id 为 `tinkers_thinking:chlorophyte` 的配方
    - `data/kubejs/worldgen/**` + `data/kubejs/forge/biome_modifier/*.json` —— **CTI 自己加的矿物生成**
    - 判断方法：`grep -rn "<item_id>" kubejs/ config/ mods/<某模组>.jar`；kubejs/data 里没有对应文件、`cti-*.jar` 的 `data/` 里也没有，就说明该配方**保持原模组原样**。
  - ⚠️ **这个仓库的 `mods/` 目录不完整**：有些模组 jar 未被收录，但它的配置在（实例：`config/tofucraft-common.toml` 有、`tofucraft` jar 没有；`forgeautofish-client.toml`、`cfm-*.toml` 同理）。所以"mods/ 里找不到 jar"**不能**直接推断"整合包没有这个模组"——要再看 `config/` 是否有它的配置文件，以及任务书是否引用它的物品 id。反例：**整合包里没有神秘农业本体**（任务书原话"本包没有神秘农业"），只是多处拿它当参照物打比方。
- 任务书独立仓库（更小、更方便 grep）：**`Team-Innova-Constructors/cti-quests`**（3.2 MB）
- 版本对照：2026-10-13 时 `CTI-server` 最新提交 `26a70b9`（2026-10-02），包内 `Tinkers-Thinking-0.1.3.4.jar`、`TConstruct-1.19.2-3.8.5.58.jar`。

## 3. MC百科（模组层面的配方与物品说明）

- 搜索入口：**<https://search.mcmod.cn/s?key=关键词>**（注意是 `search.` 子域；`www.mcmod.cn/search/` 会 404）
- 物品页 / 合成表页：`/item/<id>.html`、`/item/tab/<id>.html`；模组页 `/class/<id>.html`
- 用途：查**模组原生**配方最快（注意：**不反映 CTI 的魔改**，只看模组本体行为）
- 整合包页：<https://www.mcmod.cn/modpack/989.html>（介绍 / 包含模组 / 整合包教程 三个标签）

## 4. 已知的数据获取坑

- mcmod 的**推荐/收藏是登录态数据**：匿名抓取会拿到 `null`，而 `scripts/mcmod/scrape.mjs --pack-only` 会把它直接覆盖进 DB（`--pack-only` 路径没有"未登录"警告）。容器浏览器 2026-10-13 起已处于未登录状态。
- GitBook 的 `?ask=` 问答接口（llms.txt 里宣传的）实测**恒返回 500**，不可用；直接抓 `.md` 页面。
- 叶绿系（叶绿素矿石 → 叶绿混合物/叶绿锭）**被 CTI 改过**：CTI 自己加了丛林/竹林的矿石生成（y 0~40、6 团/区块），并新增了 `tinkers_thinking:chlorophyte`（叶绿素矿石 → 熔炼 → 叶绿混合物）。任务书原话："叶绿矿可以在丛林浅层被找到（注：包里的叶绿矿没法种，挖一些够用了）"。
