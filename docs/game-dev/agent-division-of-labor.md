# Agent 协作分工与验证产物

**状态**：生效 · **建立**：2026-11-03 · **来源**：`docs/research/ai-agent-gamedev-2026-11-03/report.md`
**用途**：单人 + agent 开发单机游戏时的分工边界。本文件可直接复制为游戏工程根目录的 `AGENTS.md`。

## 一条判据

**AI 的收益由"输出能不能被机器判定对错"决定**，不由任务大小决定。

有验证器 → 有实测级收益；没有验证器 → 没有证据表明有收益，且存在反证。所以下面每一行都必须回答：**靠什么校验**。

## 分工表

| 环节 | 主导 | 靠什么校验 | 必须带的验证产物 | 失败形态 |
|---|---|---|---|---|
| 设计与方向 | 人 | 一句话可判定的目标 + 验收标准 | `docs/design/<系统>.md`：目标、失败条件、不做什么 | 实现跑偏，几个月后才发现 |
| 技术架构 | 人 | 接口、不变量、CI 规则 | 接口签名 + 不变量清单 + `AGENTS.md` 条目 | 架构只活在记忆里，代码长成 AI 的默认口味 |
| 调研与资料 | AI | 带引用的证据落盘 | 每条结论附 URL + 原文引文 + 检索日期 | 合理但错的填充 |
| 代码实现 | AI | 以一次可观测检查为界，不按函数切 | 测试 / 日志断言 / 截图，三者至少一项 | 写了但没接上（函数从未被调用） |
| 调试 | AI 优先 | 结构化事件日志 + 状态差分 | 能定位到 `tick` + `entity_id` 的日志片段 | 偶发、竞态、只在长局出现的问题 |
| 回归与复现 | AI 建，人定优先级 | 固定 seed + 一条命令重跑 | `seed + 指令序列 + 复现命令` | 分不清是修好了还是这次没复现 |
| 平衡与调参 | AI | 无头批跑 + 指标分布 | 批跑结果 JSON（分布，不是单局结论） | 数值平衡了，手感没平衡 |
| 辅助工具 | AI | 工具自身有测试 | 工具的单测 | 工具错了，污染它产出的全部结论 |
| QA / 关卡遍历 | AI | 自动跑图 + 运行时断言 | 遍历报告 + 失败断言清单 | 玩家真会做的怪操作 |
| 美术资产 | AI | 色板 / 光照 / 描边 / UI 栅格的硬规则 | 规则检查结果 + 与既有资产的同屏截图 | 单个都还行，放一起不像一个游戏 |
| 首屏与封面 | 人判断，AI 出稿 | 愿望单转化实测 | 转化数字（不是"我觉得好看"） | 根本没人点进来 |
| 手感与节奏 | 人 | 只能自己玩 | 无（明确的人工闸门） | 无解，这是最后一道人工闸门 |

**读法**：「主导」指**谁对结果负责**，不是谁敲键盘。左列写「人」不代表亲手做，而代表这一行出错时只有人能发现。

## 六条硬规则

**R1 · 架构必须落成机器可查的东西。**
决定「资源用事件总线、寻路走流场」之后，必须写出接口签名、不变量（资源非负、单位不重叠、无死锁）、CI 规则。没写下来的架构，三个月后不存在。

**R2 · 委派的粒度 = 两次检查之间积累的未验证判断数。**
不是按函数切。只要运行时能持续给出信号，一次改动可以很大；没有信号时，再小的改动也是赌博。

**R3 · 观测优先，确定性第二。**
先做结构化事件日志（日常 90% 的 bug 靠它）；确定性回放排第二，因为**没有它就无法回答"是修好了还是这次没复现"**，也跑不了平衡批。两者覆盖的 bug 类型不重叠，都要有，只是顺序不同。

**R4 · 运行时断言覆盖"写了没接上"。**
LLM 最危险的错误不是写错，是写对但从未被调用（实测：Unreal 任务 90% 准确率 / 10% 完成度）。这类错误能通过 code review 和单元测试，只有运行时断言能抓住。

**R5 · 没有验收条件的交付不接受。**
每次委派必须写清：目标、输入、验收、边界、不做什么。验收条件写不出来，说明这件事还没想清楚，不该开工。

**R6 · 三件事不可外包。**
设计与方向、整屏视觉一致性、手感与节奏。其余环节可以由 agent 主导，人负责抽样复核。

## 给 agent 的日志规格

观测优先意味着日志是给人看还是给 agent 看，要求不同：

- **结构化**：JSON 行，字段固定，不用自由文本；
- **可定位**：每行带 `tick`、`entity_id`、`event`、`delta`；
- **差分而非快照**：写「这回合变了什么」，比写「现在是什么」有用得多；
- **错误自带上下文**：出错时附最近 N 条事件、相关实体状态、当前指令；
- **稳定 ID 可 grep**：能直接搜到「这个行为从第几 tick 开始异常」。

## 交接卡模板

```
目标：<一句话，可判定>
输入：<需要读的文件/数据/状态>
验收：<机器能判定的检查，或明确写"人工签署">
边界：<不许改的部分>
不做：<明确排除的范围>
```
