# 综合推荐：技术栈 + 品类

**输入：** 三轮调研（引擎与 2D/3D 取舍、3D 低模品类、Steam 饱和度与细分）。
**约束：** 单人、Godot、强程序、弱美术、中小体量、6–12 个月、¥10–30、Steam。
**日期：** 2026-11-02

## 推荐

> **做一个「3D 低模 · 小型殖民地 + 轻自动化」游戏：一张地图、垂直空间、30–60 分钟一局、¥30、6–9 个月。**

一句话卖点：**RimWorld 的循环，但基地是立体的**——RimWorld 是 2D 平面，3D 低模能做“多层基地 + 垂直物流 + 承重/坍塌”，这是 3D 才成立的机制，也是你唯一能低成本做出的差异化。

### 为什么是它

| 维度 | 证据 |
|---|---|
| 市场 | Colony Sim 细分中位 **$51k**（187 款）、Base Building **$37k**（329 款）、Automation **$17k**（244 款）[S1] |
| 淘汰率 | Management/Sandbox/Building 类在 2026 样本里零评测率 **53–58%**，低于 Action 的 85% [S2] |
| 技术适配 | 无角色骨骼动画、道具可复用、固定/半固定相机——正好绕开 AI 3D 的短板（脸、手、权重）[S3] |
| 个人优势 | 系统、数值、程序化、AI 管线：全是编程侧能力，不依赖审美判断 |
| 避开红海 | 不进 Action/Casual/Platformer/Horror/Roguelike 本体；不碰 Open World Survival Craft（团队体量） |

### 不选另外两个“看起来也行”的原因

- **Roguelike Deckbuilder（$28k）**：市场很好，但核心资产是卡面美术与文本量，且 2D 为主；3D 化（桌面/牌桌）会削弱“构筑”的阅读效率。**留作第二款**。
- **Management / 店铺模拟（$19k）**：最容易做完，但内容更新是无底洞，且与“殖民地”相比缺少系统纵深。**留作 3–4 个月的小体量试水**。

## 技术栈

| 层 | 选择 | 理由 / 备注 |
|---|---|---|
| 引擎 | **Godot 4.7**（Forward+） | 4.7 的 HDR/合成改进；3D 用 Forward+，不做移动端 |
| 语言 | **GDScript 为主**，热点再考虑 C# | 迭代速度优先；C# 只在模拟规模真的顶不住时引入 |
| 3D 生成 | **Tripo P2**（四边面、500–25k quad） | 游戏级拓扑；P2 每模型 100 credits，Pro $20/月≈30 个 |
| 硬表面/绑定 | **Meshy**（Auto-Rig + 600+ 预设动画，订阅内免费） | 道具与角色初绑；权重需清理 |
| 动画 | **Mixamo** + Meshy 预设 + Godot 骨骼重定向 | `BoneMap` + `SkeletonProfileHumanoid` + **Overwrite Axis** |
| DCC | **Blender**（+ headless 脚本） | 合并、法线、导出 GLB、批量烘焙 |
| 风格统一 | **一个卡通/三平面 ShaderMaterial + 8–12 色板 + 固定方向光 + 雾** | 把 AI 资产的差异压平；这是“像不像一个游戏”的关键 |
| 2.5D 逃生舱 | `SubViewport` 批量烘焙 8 方向序列帧 | 若 3D 观感不成立，资产不重做即可切 |
| UI | Godot Control + 主题资源 | 模拟类 UI 工作量大，提前做组件库 |
| 数据/存档 | 自定义 Resource + JSON，确定性模拟 | 便于 headless 测试与回归 |
| 测试 | 无头跑模拟（`--headless`）+ 固定种子回放 | 你对程序有信心，就把“可验证”做成基础设施 |
| 构建/发布 | GitHub Actions 导出 + **butler** 上传 Steam | 每次提交出可玩包，避免“只在编辑器里能跑” |
| Steam | **GodotSteam**（成就/云存档/工坊） | 4.23.2 对应 SDK 1.65，支持 Godot 4.4+ |
| AI 编码 | 只用于样板与工具脚本，核心架构手写 | 避免“AI 生成的系统没人能维护” |
| 版本管理 | git + LFS（模型/贴图） | 资产二进制多，早配 LFS |

## 资产预算

| 类别 | 数量 | 来源 | 预计工时 |
|---|---:|---|---:|
| 建筑（3 级 × 12 种） | 36 | Tripo P2 + 手工模块化 | 36–50 h |
| 道具/装饰 | 80–120 | AI + 换材质/缩放 | 25–40 h |
| 地形模块 | 8–12 | 手工建模 | 8–12 h |
| 角色（可选，1–2 种） | 2 | AI + 自动绑定 + 预设动画 | 6–10 h |
| 图标/UI | 40–60 | AI 2D + 统一描边 | 10–15 h |
| **合计** | **~200** | | **85–130 h** |

AI 订阅成本：Tripo Pro + Meshy Pro ≈ **$40/月 × 4–6 个月 = $160–240**。真正的成本是清理时间，不是 credits。

## 12 个月节奏（可压缩到 9）

| 阶段 | 产出 | 通过标准 |
|---|---|---|
| M1 | 垂直切片：放建筑、指派工人、一条生产链、昼夜 | 15 分钟内能玩出“再来一局”的冲动 |
| M2 | 核心循环 + 存档 + UI 组件库 | 存档跨版本可迁移；30 单位 60fps |
| M3–4 | 内容 pass：12 建筑、20 资源、8 事件 | 一局 45 分钟不重复 |
| M5 | 商店页 + Demo + 愿望单启动 | 首月愿望单 > 3,000 |
| M6 | Next Fest | Demo 留存 > 25% |
| M7–8 | 打磨、本地化（中英 + 3 语）、Deck、成就 | Deck Verified 指标全过 |
| M9 | 发售（¥30，首发 9 折） | — |

**Kill / 转向标准（写死，避免沉没成本）：**

- M1 结束：切片不好玩 → 换品类，不要换引擎。
- 单个道具 > 45 分钟、角色 > 4 小时 → 修管线，不要硬做。
- M3 结束：30 单位 < 60fps（目标硬件）→ 降模或切 2.5D 预渲染。
- M5 结束：愿望单 < 1,500 → 推迟发售，先改商店页与 Demo。

## 与市场数据的对应

- 目标不是“中位 $51k”，而是**进入 Colony/Base 的前 30%**：按 ¥30 定价，$51k 毛收入约等于 1,700 份；做到 5,000–8,000 份就是 ¥100–160 万毛收入，已经和《领地》同量级。
- 这个量级需要的不是“更多内容”，而是**一个能一句话说清的空间机制**（垂直基地）+ **一张能看懂玩法的封面**。
- 3D 低模的真正风险不是画面，是**“看起来像素材拼盘”**——所以着色器与色板要在 M1 就定稿，不能留到后期。

## 备选与切换

| 情况 | 切换 |
|---|---|
| 3D 观感始终不成立 | 同一批资产烤成 2.5D 精灵（等距像素风），玩法不变 |
| 想做更短平快（3–4 个月） | 3D 桌面版 Roguelike Deckbuilder（$28k 中位） |
| 想先验证发行流程 | 单场景 Management/Shop Sim（$19k 中位），当练手作 |
| 引擎层面受挫 | 不换引擎；Godot 已能承载 3D 商业作品（Road to Vostok 单人 70 万愿望单） |

## 风险清单
1. **风格统一**：最大风险。对策：M1 定稿着色器 + 色板 + 光照，之后不再改。
2. **内容量**：殖民地类的隐形工作量在“建筑组合与数值”，不在模型。把建筑做成模块化（墙/地板/屋顶/设备），用组合换数量。
3. **AI 3D 迭代**：工具半年一代，管线按“可替换”设计（GLB + 标准人形骨架）。
4. **Godot 4.7 的 3D 性能回退**：固定视角低模受影响小，但 M2 必须在目标硬件上测。
5. **披露**：AI 资产照实披露；不要用 AI 封面做出“比游戏好看”的落差。

# 修订（2026-11-02 晚）：AI 决策能力带来的调整

**触发：** 讨论了“让 AI 像玩家一样做战略决策”（Jev 填策略表 + 规划器），确认这是本项目唯一能低成本做出的差异化。

## 修订结论

**改，但不是改成“策略游戏”，而是把殖民地底盘改造成“殖民地 + 一个会算计你的对手派系”。**

| 项 | 原方案 | 修订 |
|---|---|---|
| 品类 | 小型殖民地 + 轻自动化 | **同一底盘 + 单一可读的对手领袖**（外交/贸易/袭扰） |
| 差异化 | 垂直基地（3D 才成立的机制） | 垂直基地 **+ 一个决策可读的对手** |
| AI 投入 | 未计 | 额外 4–6 周（Agent 接口 + 策略表 + 表达层） |
| 体量 | 6–9 个月 | **9–11 个月** |
| 定价 | ¥30 | ¥30（不变） |

## 为什么不换成纯策略

| 细分 | 中位毛收入 | 在售 | 判断 |
|---|---:|---:|---|
| Colony Sim | $51,000 | 187 | 原选，最高 |
| Base Building | $37,000 | 329 | 原选 |
| Tactical RPG | $16,000 | 171 | AI 收益小（敌方单位决策简单） |
| Grand Strategy | $14,000 | 139 | 内容量是团队级 |
| 4X | $11,000 | 74 | 单品级做不动（科技树+地图+战斗+外交） |
| RTS | $10,000 | 262 | 单位 AI 与操作门槛双高 |
| Turn-Based Strategy | $8,000 | 574 | 红海 |
| Turn-Based Tactics | $8,000 | 495 | 红海 |

纯策略类的中位只有殖民地类的 **1/3–1/5**，而“AI 会决策”这件事在纯策略里也未必被玩家感知——它需要内容量（科技树、单位、外交选项）来承载，那正是单人做不完的部分。

## 为什么必须把 AI 用上

1. **这是你唯一能便宜做出的差异化**：程序强 + 美术弱 + 有 AI 工具链，正好落在“系统与决策”这一侧。
2. **殖民地类缺一个“人”**：RimWorld 的对手是环境与事件，玩家骂的是随机性；加一个会结盟、会背刺、会趁火打劫的邻居，情绪张力立刻不同。
3. **它同时解决留存**：一局 45 分钟的重复性，靠“这次它为什么背叛我”来支撑，比再加 6 种建筑有效。

## 但有一个关键前提：AI 必须可读

玩家不会为“我的对手用了决策模型”付费。历史上卖“聪明 AI”的游戏几乎都失败（除 FEAR、Alien Isolation 这类把 AI 做成恐怖体验的）。

所以卖点必须落在**玩家能看见的行为**上：

- 使者来访、条约文本、边境集结、贸易封锁、背刺前的征兆；
- “为什么”面板（它对你的态度、它的困境）；
- 事件日志里能回溯“它三个月前就开始囤粮了”。

**宣传素材里写“会记仇、会结盟、会趁你饥荒时来谈判”，不写“AI 决策模型”。**

## 由此产生的三条硬约束

1. **只有一个对手领袖**（不是 4 个派系），否则 AI 工作量 ×4 且玩家记不住谁是谁。
2. **AI 的决策频率是“每回合/每 N 秒一次”**，不是每单位每 tick —— 这样才能用查表（微秒级），而不是实时模型。
3. **没有对手也能完整玩**（沙盒模式），把 AI 当作可选难度与戏剧性来源，而不是核心循环的依赖。

## 修订后的最小切片（M1，3 周）

- 1 张地图、6 种建筑、2 种资源、1 条生产链；
- 1 个对手领袖，只有 4 个意图（扩张/备战/结盟/袭扰），走 3×3×3 的小表（27 格，手写即可）；
- 1 个可见通道：使者来访 + 一条“它最近在干什么”的传闻；
- 通过标准：**不告诉测试者 AI 的存在，看他们会不会主动提起“那个邻居”**。

# 自我质疑：这个设计值不值得做

**先给结论：会有人玩，但按现在这个设计，大概率不够回本。**

## 一、算一笔最基础的账

品类中位毛收入 $51k。按 ¥30（实收约 $4.2/份）算：

$$51{,}000 \div 4.2 \approx 12{,}100 \text{ 份}$$

也就是说，**要在 ¥30 的定价下“达到 Colony Sim 的中位数”，需要卖 1.2 万份**。而独立游戏的整体中位数是几百份。所谓“中位品类”，实际对应的是前 5–10%。

对照《领地》——¥58、13 种语言、联机、工坊、4 万份，是我们讨论过的成功案例。它的收入 ≈ $337k，是品类中位的 6.6 倍。

**定价决定难度**：同样做到 $51k，¥30 要 1.2 万份，$15 要 3,400 份，$25 要 2,000 份。低价不是“更容易卖”，是“需要多卖 6 倍”。

## 二、竞争对象不是中位数，是具体的那几款

Colony Sim 的玩家手里有：RimWorld（$35，十年内容 + 海量 mod）、Dwarf Fortress（免费/$$）、Oxygen Not Included、Against the Storm、Manor Lords。

一个 9–11 个月、单人、3D 低模的作品，在“内容深度”这条轴上必输。它唯一能赢的轴是**主题与叙事密度**——而当前设计把主题写成了“殖民地”，把叙事写成了“可选”。

## 三、我犯的方法错误

我用 tag 中位数选品类。但**中位数是“有钩子的游戏”挣来的，选了 tag 不等于有钩子**。这是典型的选择偏差：看到 Colony Sim 中位 $51k，就以为“做殖民地”能拿到 $51k。

真实的因果是反的：那群游戏先有一个强幻想（“在冻土上守住最后一座炉城”“在废墟里活过 30 天”），然后恰好落在 Colony Sim 这个 tag 上。

而我的设计是从“3D 低模 + 垂直基地 + 弱美术”倒推出来的——**技术约束在前，玩家幻想在后**。这是它最根本的弱点。

## 四、3D 低模在这个品类是负债

殖民地类的传播方式是截图：玩家晒自己搭的基地。内容密度就是画面密度。低模 + AI 资产在这个品类里读作“省成本”，而不是“风格”。

反过来，2D/像素在这个品类反而安全（RimWorld、Dwarf Fortress 都证明了），因为玩家接受“用想象力补”。

## 五、如果还要做，我会这样改

1. **从“一局”而不是“无限”出发**：2–4 小时有结局的一局，像 Frostpunk / Against the Storm，而不是无限经营。内容量可控，评价标准明确。
2. **垂直性是主题，不是机制彩蛋**：塔城/矿井/楼层 = 阶层与防线，塌方与封锁本身就是叙事。
3. **砍到 3 种资源、无科技树、无自动化**：把省下的时间全给“对手会做什么”和“事件文本”。
4. **定价 ¥45–58**：同样收入只需 1/4 的量；也让“小而精”成立。
5. **卖点写成幻想，不写机制**：trailer 前 15 秒是“楼上那位在你断粮第三天来敲门”。

## 六、诚实的概率估计（我的判断，不是数据）

| 结果 | 概率 |
|---|---|
| 回本（覆盖 10 个月机会成本，约 ¥15–20 万） | **约 25%** |
| 达到品类中位（1.2 万份 @ ¥30） | **< 10%** |
| 卖不到 1,000 份 | **约 40%** |

## 七、两周内可以做的证伪

1. 做 3 张 capsule + 1 段 15 秒 GIF（不用做游戏），挂 Steam 页面；
2. 投 $200 广告或发 3 个社区，看愿望单转化率；
3. **转化 < 5% 就换题材**，不要靠“做出来再看”。

这比做 9 个月再发现没人要便宜 100 倍。
