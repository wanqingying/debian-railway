# LLM-as-judge 判定器 · v1 / v2 / v3 对比（2026-11-04）

模型：`opencode-go/deepseek-v4.1-flash`（chat，非 decision model）。
样本：60 条（RAID 长摘要 20、HC3-en 短问答 20、HC3-zh 中文短问答 20），human/ai 各 30。
判定口径：`AI` + `LIKELY_AI` = 判 AI；`LIKELY_HUMAN` + `UNCERTAIN` = 判人（即「弃权算判人」，对保守检测器有利，故另列「剔除 UNCERTAIN」）。

## 结果

| 版本 | 准确率 (95% CI) | 弃权率 | 召回(AI) | 误报(human) | 剔除弃权后 | AUC(p_ai) |
|---|---|---|---|---|---|---|
| v1 | 95.0% [86.3–98.3] | 31.7% | 90.0% | 0/30 | 97.6% | 无 p_ai |
| v2 | 91.5% [81.6–96.3] | 25.4% | 86.2% | 1/30 | 95.5% | 0.970 |
| v3 | 93.3% [84.1–97.4] | 28.3% | 86.7% | 0/30 | 97.7% | 0.980 |
| **v4（采用）** | **95.0% [86.3–98.3]** | **11.7%** | **90.0%** | **0/30** | **98.1% [90.1–99.7]** | **0.986** |

分数据集（v4）：RAID 85.0% / 弃权 25% / 召回 70%；HC3-en 100% / 5% / 100%；HC3-zh 100% / 5% / 100%。

**最终采用 v4 + 阈值 `≥0.75 判 AI / 0.30–0.75 不确定 / <0.30 人类倾向`**。它取消了模型自选档位，只让它输出 `p_ai` 与证据，档位由调用方切；因此同样的准确率下可判定比例从 v1 的 68.3% 提到 88.3%，且第一次能按「误报预算」反推阈值。详见 `README.md`。

`p_ai` 的分离度：AI 样本均值 0.848，人类样本均值 0.184。

## 三次改动的实际收益

1. **v1 → v2**：弃权率 31.7% → 25.4%，回收 6 个百分点；修好了 RAID 里两条被噪声误导的 AI 文本（`raid-a0001600` 的 LaTeX 残留、`raid-a0002600`）。代价是引入 1 条误报：`HC3-zh-h9`（中文真人回答）被判 `AI`，置信度 0.9——这在真实使用中是能引发投诉的错误，正是报告里「非母语/规整文本是最大误报源」的那一类。
2. **v2 → v3（加 E 族整体判读）**：误报回到 0/30，AUC 0.970 → 0.980，但召回从 86.2% 掉到 86.7%（基本持平，换回 1 条又丢 2 条：`raid-a0000601` 与 `HC3-zh-a9` 从「判 AI」退回 UNCERTAIN）。**E 族在 60 次输出里被引用 0 次**——模型从没把判决归因给 E，所以「整体判读」这一条目前只是写了、没有可验证的作用。
3. **v3 vs v1**：14/60 条判决不同，其中 RAID 人类样本 3 条从 UNCERTAIN 变成 LIKELY_HUMAN（信息量阈值生效），`raid-a0002600` 从弃权变判对。综合看 v3 是三者中最好的：零误报、最高 AUC、弃权率低于 v1。

## 结论

- **v4 采用**：取消模型自选档位，只让它输出 `p_ai` + 证据，档位由固定阈值生成（`≥0.75` AI / `0.30–0.75` 不确定 / `<0.30` 人类倾向）。在同样 95% 准确率与 90% 召回下，弃权率从 v1 的 31.7% 降到 11.7%，判定后准确率 98.1%（53/60），AUC 0.986。
- **v1 的名义准确率 95% 是弃权堆出来的**，不可与后续版本直接比较；v1 与 v4 准确率相同，但 v4 多判定了 20 个百分点。
- **v2 的「更激进」是拿误报换的**：`HC3-zh-h9`（中文真人回答）被判 `AI` 且置信度 0.9，属不可接受的一类错误。
- **E 族保持但降级为「未验证」**：60 次输出里被引用 0 次，不写进对外结论，等更难的数据集再做消融。
- 仍然存在的短板：RAID 召回 70%——三条漏判全是「AI 生成的学术摘要」，且其中两条带 PDF/OCR 噪声（`\begin{paracol}{2}`、`end –to -end`），说明噪声仍会被读成人味。

## 阈值选择

人类样本 p_ai 分布 `0.04 … 0.45` + 离群 `0.73`；AI 样本 `0.72 … 0.98` + 离群 `0.22 / 0.35`。扫描结果：

| 阈值 | 召回 | 误报 | 可判定 |
|---|---|---|---|
| 0.60 | 93% | 1/30 | 55/60 |
| 0.70 | 93% | 1/30 | 55/60 |
| **0.75** | **90%** | **0/30** | **53/60** |
| 0.85 | 87% | 0/30 | 52/60 |
| 0.90 | 57% | 0/30 | 43/60 |

选 0.75：它是唯一同时给出零误报与 90% 召回的点。

## 工程事故记录（已修）

v2/v3 第一次跑出的数字（86.5% / 89.7%、8 条解析失败）**不可用**，原因是 `judge.mjs` 用 `String.replace` 做占位符替换：v2/v3 的提示词顶部有一行「用法：替换 `{{TEXT}}`」的说明，`replace` 只替换第一个匹配，于是整篇文章被塞进了那行说明，正文槽位仍然是字面量 `{{TEXT}}`；模型看到未替换的占位符后有两例直接回问「是不是没填文本」。

修复：改用 `replaceAll`，并在渲染后断言「不含 `{{TEXT}}` 且包含正文前 40 字」，否则直接抛错而不是把污染结果写进统计。同时让 `judge.mjs` 记录 `p_ai` / `rule` / `noise` 字段，才可能算出 AUC。

教训：**评测脚本的输入渲染必须自校验**，否则一个字符串替换语义的差异会让整轮数字失真，而且表面上看起来只是「模型变差了」。
