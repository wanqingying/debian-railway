# AI 文本判定器（judge）— 采用方案

一句话：**让聊天模型只出「证据 + p_ai」，档位由固定阈值切出来**。不靠模型自己的"感觉"给结论，因此结论可复现、可标定、可审计。

## 采用的阈值（v4）

| p_ai | 输出 | 含义 |
|---|---|---|
| ≥ 0.75 | **AI** | 可对外说「很可能由模型生成」 |
| 0.30 – 0.75 | **不确定** | 证据不足，不表态 |
| < 0.30 | **人类倾向** | 只表示「不像机器」，不等于证明是人 |

阈值依据：60 条实测（RAID 长摘要 / HC3-en / HC3-zh 短问答，各 20 条，人机各半），人类样本的 p_ai 分布是 `0.04 … 0.45` 加一个离群 `0.73`，AI 样本是 `0.72 … 0.98` 加两个离群 `0.22 / 0.35`。**0.75 是唯一同时给出零误报和 90% 召回的点**；降到 0.60 会多抓 1 条 AI，代价是误报 1 条真人文本。按报告结论（压误报比追召回更影响结论价值），选 0.75。

## 实测（DS v4.1 Flash，60 条）

| 版本 | 准确率 | 弃权率 | 召回(AI) | 误报 | 判定后准确率 | AUC |
|---|---|---|---|---|---|---|
| v1（模型自选档位） | 95.0% | 31.7% | 90.0% | 0/30 | 97.6% | — |
| v2 | 91.5% | 25.4% | 86.2% | 1/30 | 95.5% | 0.970 |
| v3（+E 族） | 93.3% | 28.3% | 86.7% | 0/30 | 97.7% | 0.980 |
| **v4（阈值切档，采用）** | **95.0%** | **11.7%** | **90.0%** | **0/30** | **98.1%** | **0.986** |
| v5（自主判读可改分） | 91.7% | 15.0% | 83.3% | 0/30 | 98.0% | 0.983 |
| v6（v5 去掉体裁双重扣分） | 91.7% | 21.7% | 83.3% | 0/30 | 97.9% | 0.979 |

v4 相对 v1 的收益不是准确率（同为 95%），而是**同样的准确率下多判定了 20 个百分点**：可判定比例 68.3% → 88.3%。

## 自主判读：试过让它改分，结论是不让它改

用户要求「让模型自己整体判断一次」。做了两轮（v5、v6），让它输出 `auto.lean` 并允许用 `e_shift`（±0.2）修正证据分：

- **它单独判断的能力是真实的**：`auto.lean` 只看「像不像」时，v5 准确率 88.3%（AI 26/30、人类 27/30），v6 是 83.3%，而且**一次误报都没有**。这个水平已经接近整条流水线，说明实体证据之外确实有可用信号。
- **但它给自己的权重是坏的**：v5 的 60 条里 32 条非零 `e_shift`，其中 **30 条为负**；v6 收紧后仍有 25/28 为负。这是系统性下调，不是信号——模型把「下调」当成稳妥。
- 后果直接可见：召回从 v4 的 90%（27/30）掉到 83.3%（25/30），可判定率反而变差，AUC 也没超过 v4（0.979–0.983 vs 0.986）。

所以最终方案是 **v4 的打分逻辑，自主判读只在旁证里保留**：可以做特征、可以人工复核时参考，但不改 `p_ai`。原因是它与证据分高度相关（同一条判断的两个视角），一旦独立加权就等于把同一个信号算了两遍，而它又没有任何校准。

## 跑法

```bash
node fetch-datasets.mjs                                  # 生成 items.jsonl（每数据集 ≤20 条）
node judge.mjs --prompt prompt-judge-v4.md --out results-v4.json --concurrency 4
node compare.mjs                                         # v1–v4 并排表
```

- `judge.mjs` 走本地 opencode HTTP API（`127.0.0.1:4096`，basic auth `opencode:qingying`），每条样本一个全新会话、目录 `/tmp/opencode/judge-run`，并发 4。
- 默认模型 `opencode-go/deepseek-v4.1-flash`。**必须显式指定**：服务器默认模型是 `commandcode/deepseek-v4-1-flash`，该 provider 无额度。换模型：`--model opencode-go/glm-5.3`，推理档：`--variant high`。
- 渲染自校验：替换后若仍含 `{{TEXT}}` 或找不到正文前 40 字，直接抛错——不做这一步，提示词顶部提到占位符的一行会把正文吃掉，整轮数字失真（已踩过）。

## 换到自己的语料前必须做的标定

阈值 0.75 是在**上述三个公开数据集**上定的，不能直接搬到中文论坛短帖。真要用于生产：

1. 收集 200–500 条**同分布**已标注样本（同一体裁、同一长度段、同一来源渠道）。
2. 跑 `judge.mjs` 拿到 p_ai。
3. 画 ROC，取「误报 ≤1%」对应的阈值，写回 `judge.mjs` 的 `derived` 与提示词头部。
4. 只看判定后的准确率（98% 那种数字必须标出覆盖率，否则没有意义）。

## 已知短板

- **带 PDF/OCR 噪声的学术摘要最容易误判**：`\begin{paracol}`、`end –to -end` 这类残留会被读成"人味"，两个 0.22/0.35 的漏判都在这儿。提示词已写明"噪声不构成任何方向"，模型仍守不住——这是当前最主要的失效模式。
- **改写过的 AI 文本**不在评测范围内（RAID 只取 `attack=none`）。按报告，25% 同义词替换就足以打掉大部分统计检测，本方案同样弱。
- **输出格式的稳定性**：v4 的 JSON 比 v3 长，模型偶尔会写尾随逗号、截断对象、或在值里塞英文双引号。`judge.mjs` 现在按候选对象逐个解析并做三种修复（去尾随逗号、去 `,"}` 碎片、补齐括号），单轮 60 条的解析失败率从 28% 降到 0；仍失败的条目会被记录到 `/tmp/opencode/judge-fails.jsonl` 供单独重跑。
