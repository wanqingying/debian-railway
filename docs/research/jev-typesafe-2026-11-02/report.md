# Jev（TypeSafe）能不能当游戏里的决策模型

**问题：** https://docs.typesafe.ai 的 Jev 能否直接用于游戏决策（派系领袖/首领/队友）？能否内置？
**日期：** 2026-11-02

## 结论

**Jev 确实是“决策模型”，而且是目前最接近你想要的东西——但它是云 API，不能内置；而且它只做判断，不做规划。**

| 你的诉求 | Jev 能否满足 |
|---|---|
| 给定局面，从候选里选一个（扩张/备战/结盟/背刺） | ✅ 原生 `Choice`，还带概率分布和 confidence |
| 给局面打分（缺粮严重程度、玩家威胁度） | ✅ 原生 `Score`（有序档位 + 概率） |
| 判断真假（“玩家正在集结兵力”） | ✅ 原生 `Noul`（0–1 概率） |
| 一次调用问多个问题 | ✅ 并行评估，加问题几乎不加时间 |
| **多步规划 / 长程目标** | ❌ 明确不支持，官方要求“拆成原子问题，用代码组合” |
| **内置进游戏（离线、无网、无 key）** | ❌ 只有云 API，不提供权重、不支持自托管/微调 |
| 中文内容 | ⚠️ 官方说英文最好，CJK 可用但需自测 |

## 关键事实（官方文档）

- 端点：`POST https://api.typesafe.ai/v1/systemone`，Bearer key。
- 模型：`jev-1.14.0` / `jev-1.13.0`，**$42 / Btok**（即 $0.042 / 百万输入 token），**输出免费**。
- 上下文：64k/请求、32k/问题；长上下文 262k（需 header，更慢更不准）。
- **只接受文本**：字符串、JSON、文本数组。
- **不针对客户微调**：同一套权重服务所有账号，你只能通过 `state` 和 `instructions/criteria` 塑造行为。
- 输出是校准过的概率 + confidence，不生成解释。

## 成本：这是它相对 LLM 的最大优势

一次调用 = 状态（约 2,000 token）+ 问题（约 400 token）≈ 2.4k 输入 token ≈ **$0.0001/次**。

| 场景 | 调用量 | 成本 |
|---|---:|---:|
| 4 个领袖，每分钟一次，10 小时 | 2,400 次 | **$0.24** |
| 4 个领袖，每 2 分钟一次 | 1,200 次 | $0.12 |
| 同规模用 gemini-flash-lite 做决策 | 2,400 次 | 约 $0.49 |

单位成本比“用 LLM 做决策”低两个数量级，因为输出不要 token、问题并行。**在开发/测试阶段，这个价格基本可以忽略。**

## 但它解决不了“内置”

三个硬约束：

1. **没有可下载的权重**，也没有本地推理 SDK；文档明确“不针对客户微调，同一权重服务所有账号”。
2. **单机游戏的云依赖**：一款 ¥30 的买断制游戏，如果核心 AI 依赖一家 2026 年成立的公司，服务改价/下线/改模型版本，你的游戏就坏了。对长尾销售是真实风险。
3. **Steam 规则**：现场调用的外部 AI 服务按次计费，Valve 要求你“代表玩家管理访问，并用 Steam 支持的支付方式收费”[S2]。

## 真正正确的用法：当“老师”，不当“引擎”

Jev 的输出是**校准概率**，这恰好是最好的训练标签：

1. **离线标注**：用你的 Agent 接口跑几千个局面，问 Jev「此刻最优意图是哪一个」+「粮食紧急度」+「玩家威胁度」，把概率分布存下来。
2. **蒸馏**：用这些软标签训练一个 1–5M 参数的小网络（或直接拟合梯度提升树），导出 ONNX，塞进游戏——**毫秒级、离线、确定性、零成本**。
3. **校验**：拿 Jev 的分布对照你手写效用函数的输出，分歧大的局面就是你的权重 bug。
4. **运行时（可选）**：如果你接受在线依赖，也可以直接在游戏里调 Jev 做“意图层”，规划器仍是你的。

这也回答了你最早的问题：**“通用的决策模型”是存在的，但它是判断模型（System One），不是规划器，也不是可内置的权重。** 你要的“像玩家一样玩”，最终仍然是“规划器 + 一个判断层”，只是这个判断层可以是 Jev，也可以是从 Jev 蒸馏出来的小网。

## 建议

- **开发期**：用 Jev 做标注与校验，成本几美元，价值极高（它比 LLM 稳、比手写规则快）。
- **上线版**：蒸馏成 ONNX 小网内置；Jev 作为“可选在线增强”或直接不接。
- **不要**把 Jev 当成实时决策引擎接到每个单位——它是 System One（快速直觉判断），不是 System Two（规划）。
