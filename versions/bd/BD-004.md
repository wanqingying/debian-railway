## 为什么是 `@larksuite/cli@1.0.99`

- **候选范围**：npm 上 107 个版本，`dist-tags` 只有 `latest = 1.0.99` 与 `beta = 1.0.86-beta.0`。按 P2「只跟稳定 dist-tag」，beta 排除。
- **1.0.99 是唯一候选**：2026-11-04 发布，其后无新版本；1.0.94→1.0.99 的发布间隔是 7/5/12/15/22 天，属正常补丁节奏。
- **按 BD 规则的两条判据**——①与现有栈无兼容门禁（独立 Go 二进制，只调用飞书开放平台 HTTP API，不碰 opencode / OpenChamber / magic-context）；②没有落在本使用路径上的未修重大 bug：`docs +fetch` 在 docx 与 wiki 两种链接上都实测成功（见验证记录），搜索、`--jq`、评论 sidecar 也正常。
- **体量**：npm 包本体 148 KB（只是个 JS 启动器），真正的二进制由 postinstall 按平台从 GitHub Releases 拉取，因此**需要 `--allow-scripts`**，失败形态与 `@railway/cli` 是同一类（GitHub 504 会让构建失败一次，重试即可）。
- **上游性质**（不作为选型理由，只作为风险基线）：18,024★、22.9 万次/周下载、MIT；README 自己写明「可被 AI Agent 调用，存在幻觉/提示词注入风险，建议只当私人助手，不要拉进群聊」。

## 安装与持久化（这次的实际改动）

1. **镜像烤入**：`Dockerfile` 的 `npm i -g` 那一行加 `--allow-scripts=@larksuite/cli` 与 `"@larksuite/cli@1.0.99"`。
2. **启动补装**：`scripts/install-tools.sh` 增加 `LARK_CLI_VERSION`（默认 `1.0.99`），只在 `command -v lark-cli` 缺失时 `npm i -g`，与 codegraph 的「镜像为准 + 补装路径」同一形状。
3. **凭证落卷**：lark-cli 认死 `~/.lark-cli`（`config.json`、应用密钥密文、缓存）与 `~/.local/share/lark-cli`（用户 token、DPoP 密钥、`master.key`），**既不认 `XDG_CONFIG_HOME` 也不认 `XDG_DATA_HOME`**，而 `$HOME` 每次重部署清空。`entrypoint.sh` 现在把两者分别软链到 `$XDG_DATA_HOME/lark-cli/{config,data}`（同样带「先并入真实目录、再软链」的 no-clobber 逻辑，与 `~/.config/openchamber` 那条一致）。
4. **已有授权直接继承**：本次授权（feishu-bot 应用 `cli_aa037cd604b85cc9` + 用户 `qingying`）在冻结前已从 `/root` 复制到卷上，因此上线后**不需要重新扫码**。`master.key` 与 `*.enc` 必须同时在卷上，缺一个就解不开。

## Agent skills：只烤三个，其余按需读

仓库里 28 个 skill 共 5.4 MB。镜像里只放了 `lark-shared`（配置/认证/身份，其他 skill 的前置）、`lark-doc`（文档读取、创建、编辑）、`lark-wiki`（知识空间与节点），共 172 KB。

## 关键捆绑细节 / 使用须知

- 版本看 `lark-cli --version`（输出 `lark-cli version 1.0.99`）；**没有 `version` 子命令**，写成子命令会返回 `unknown command \"version\"` 的 `ok:false` 信封——部署后第一次验证就踩了，`install-tools.sh` 的日志行已改成 `--version`。
- 输出是信封结构：成功 `{ok:true, identity, data}` 走 stdout，失败 `{ok:false, error:{type,subtype,code,message,hint}}` 走 stderr 且退出码非 0。**判成功用 `ok` 或退出码，不要看 `code`**（成功信封里没有 `code`）。
- `--jq` 的路径按信封走：读正文是 `.data.document.content`，不是 `.data.content`（按后者取会得到 `null`，我第一次就踩了）。
- 身份显式化：文档操作建议 `--as user`，发消息可 `--as bot`；`auth status` 会给出两种身份的 ready 状态。
- wiki 链接（`/wiki/<token>`）可直接喂 `--doc`，不必先换成 docx token。
- 表格保留为 HTML `<table>`（含 `colgroup`），单元格里的 @人 是 `<cite type="user" ...>`，需要人名要自己转。
- 授权流程（需要人工扫码，只能走容器里的 VNC 浏览器或用户自己的手机）：
  `lark-cli auth login --recommend --no-wait` → 拿 `verification_url` + `device_code` → `lark-cli auth qrcode <url> --output /tmp/qr.png` 展示 → 用户完成后 `lark-cli auth login --device-code <code>`。
  每次重试都会作废上一轮的 device code，**不要用短超时反复重试**。
- 风控默认开启：请求会带 OS 类型与设备型号。要关是 `lark-cli config risk-control off`，默认**不要关**。
