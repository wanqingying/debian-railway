## 为什么是这些版本

### opencode `2.2.6`

- 相对 2.2.5 的可见改动：**MCP 连接池**（`pool: true`，同配置项目共用一条连接）、**GUI 插件主题与插槽**（`ctx.ui.Select`、代码块动作、原生设置/菜单组件）、手机端 composer dock、`opencode run -w/--worktree`、`opencode run --archived`、session warming（`interval: "auto"`）、`websearch.use` 策略与 `OPENCODE_FLAGS=all`、Code Mode 字节码 VM（默认关）。
- 与会话/集成直接相关的修复：`opencode acp` 会删除客户端 `session/new` 后未发消息就关闭的空会话（Paseo / CodeNomad 这类外部 ACP 客户端不再留垃圾会话）；OpenCode Console 配置请求 5 秒超时（启动不再被挂住）；插件在更新交接失败后重启、渲染器/存储/事件流/后台服务的瞬时故障恢复。
- 本地插件影响：未见 breaking。`@opencode/plugin` 根入口未变，`sysinfo` / `session-search` 的 `Plugin.define` + `ctx.tool.transform` 不用改（升级后验证工具可调用即确认）。

### OpenChamber `2.7.0`（fork 构建）

- **兼容门禁**：`2.7.0` 包内 `server/lib/opencode/compatibility.js` 仍是 `MINIMUM_OPENCODE_VERSION = '2.2.4'`（实测），与本 BD 的 2.2.6 满足。
- **Node 门禁**：`engines.node >= 24.14.0`，镜像 Node 24.x 满足。
- **启动契约未变**（包内实测）：`OPENCHAMBER_DATA_DIR`（`bin/lib/cli-startup.js`）、`--ui-password`（`server/lib/opencode/cli-options.js`）、`POST /api/openchamber/update-install`（`server/lib/opencode/openchamber-routes.js`）全部仍在，`entrypoint.sh` 的启动参数不用改。
- **新功能（自用相关）**：`/new-extension`（agent 自己写并构建扩展，聊天里出安装按钮；扩展可在聊天里绘制、替 agent 回答提问、操作会话）、Office 文件查看与表格编辑（Word/PPT/Excel/ODF，公式与撤销，agent 改动单元格高亮）、回复里的 shell 代码块直接 Run、SQLite/Parquet/zip/Jupyter 只读查看；2.6.1 带来的 PR diff 内评审 + GitHub auto-merge、会话移动到文件夹、「空转 CPU」下降。
- **两个新依赖**：`sherpa-onnx-node`（本地语音转写，模型按需下载）与 `7zip-bin`，包体 18.2 MB → 20.1 MB。
- **fork 补丁重打**（这是本 BD 唯一的人工成本）：
  - 分支 `fork/2.7.0` = 上游 tag `v2.7.0`（`651a05648`）+ cherry-pick `3ab568fcc`（`feat(sidebar): group a project's worktrees after its own sessions`）。31 个文件，**零冲突**自动合入。
  - `bun install --frozen-lockfile` 把 `@opencode/client` / `@opencode/schema` 升到 2.2.6（与宿主对齐）。
  - `packages/web` 里 `NODE_OPTIONS=--max-old-space-size=6144 bun run build`（2 分 35 秒，内存峰值 ~11 GB），随后 `bun run pack:web` → `openchamber-web-2.7.0.tgz`（20.1 MB）。
  - 断言：`dist/assets` 里能 grep 到 `groupRootWorktrees`（构建期 Dockerfile 也做同一检查）。
- **r1：fork 的第 2 个补丁 —— ui-blocks 指引改成「root 最后写」**（`3fdff97fc`，版本矩阵不变，只换产物）：
  - **证据**：本机 40 个 `openui-lang` 块里 6 个画出「无法绘制此区块」（15%），**全部**同一形态 —— `root = Stack([t, n1])` 写在最前、`n1` 从未定义。解析器遇到「引用了未定义的名字」即整块判 invalid，不做部分渲染（`catalog.ts` 的 `parseUiBlock`，错误 `Undefined names`）。失败全部落在 600–1200 字符的块上（`< 600` 的 20 个块零失败）。
  - **根因**：指引原文 `first line root = Stack([...])` 强制了这个顺序，两个示例也在示范它；而解析器只要求 root 被定义，不要求在第一行（实测 root 写在最后照样 `ready`）。
  - **改动**：`packages/ui/src/components/chat/uiBlocks/guidance.ts` 的一句话 + 两个示例，改成最后写 root，并写明「列了没定义的名字就整块不画」；`bun run --cwd packages/ui ui-blocks:generate` 重新生成服务端副本（服务端没有解析器，只吃这份预生成文本 `packages/web/server/lib/session-knowledge/ui-blocks-guidance.js`）。
  - **效果**：同样的疏漏从「整块不画」降为「少画一个组件」；它不影响内容正确性，签名不符 / 定义未用 / 语句截断三类仍靠发送前自检。
  - **未改渲染器与服务端**：红字下面本来就打印原因（`Undefined names: n1`）且源码可展开，信息是全的，只是发生在消息发出之后。
  - 构建：`bun install --frozen-lockfile` → `packages/ui build`(tsc) → `packages/web build`（2 分 11 秒）→ `pack:web`；tarball 21,053,074 B，sha256 `22ec02bdfd3c0fc209fea105457ebee0f8b992a2cae738abfd58a984be87f625`。
- **已知未修回归（接受）**：
  - [#6084](https://github.com/openchamber/openchamber/issues/6084) 主进程按项目以约 3 次/秒 spawn `git`（2.7.0 仍 open；2.6.1 的「Less CPU for doing nothing」未针对它）。本容器 pids 上限 1000，需盯 `pids.current`。
  - [#5669](https://github.com/openchamber/openchamber/issues/5669) 侧栏 Tree 视图仍未回来 —— fork 补丁继续存在。
  - [#6108](https://github.com/openchamber/openchamber/issues/6108) 页面 `awaitAnswer` 期间若有 dispatched session 结果返回，页面会失焦。规避同上个 BD。
- **已修复，可删的旧顾虑**：[#6131](https://github.com/openchamber/openchamber/issues/6131)（`question` 表单无提交按钮）于 2026-11-07 closed。

### magic-context `0.49.43`

- **Hold 解除**：[#838](https://github.com/cortexkit/magic-context/issues/838)（v2 host fold 给无历史子会话写空摘要）于 2026-11-06 关闭（completed）。0.49.36–0.49.43 修掉同一类问题：空/漏 fold、`/compact` 收不回空间、每 pass 工作量随会话增长、失败工具调用破坏请求 schema、首次摘要后不再压缩、废弃 instruction 行塞满 OC2 窗口（0.49.42）。
- **拿回的收益**：0.49.35 引入的 host fold 提速（25k 消息会话 1.3–2.0 s → 0.33–0.49 s/step）现在可用。
- **仍 open**：[#834](https://github.com/cortexkit/magic-context/issues/834)（每 pass 复制全量历史 2–3 次），不阻断，0.49.41/0.49.42 已削减每 pass 工作量。
- **配置兼容**：`magic-context.jsonc` 的 12 个顶层键（`$schema`/`enabled`/`compaction`/`cache_ttl`/`commit_cluster_trigger`/`fail_closed_blocking`/`history_budget_percentage`/`temporal_awareness`/`historian`/`dreamer`/`embedding`/`memory`）全部存在于 `v0.49.43` 的 `assets/magic-context.schema.json`，无增无删。各版本 release notes 均写 "No database migration is needed"。

## 关键捆绑细节

- **OpenChamber 与 opencode 必须成对**：`2.7.0` 要 `opencode ≥ 2.2.4`，本 BD 的 2.2.6 满足。
- **opencode 版本真正生效的是 Dockerfile 那行**：`install-tools.sh` 只在二进制缺失时才装，两处必须同 commit 改；Dockerfile 的构建期断言已同步为 `2.2.6` / `2.7.0`。
- **magic-context 写死精确版本**，`entrypoint.sh` 启动时删掉所有**非当前 spec** 的插件缓存；`MC_PLUGIN_CACHE_SPEC` 已改为 `0.49.43`。
- **`compaction` 两个开关分属两个文件**（`opencode.jsonc` 的 `compaction.auto: false` + `magic-context.jsonc` 的 `compaction.enabled: true`），本次都不动。升级后要确认 OpenChamber 设置页里的 compaction 选项仍是关的。
- **vendor tarball 换名**：`vendor/openchamber-web-2.6.0-fork.tgz` 已删除，改为 `vendor/openchamber-web-2.7.0-fork.tgz`（`Dockerfile` 的 COPY、构建期断言、`install-tools.sh` 的默认路径同步）。
- **`update: "notify"`** 不变。
