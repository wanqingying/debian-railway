## 为什么是这些版本

### opencode `2.1.4`

- 当时 npm `latest`；2.1.x 是 OpenChamber 2.5.x 要求的最低线（2.5.1 的 `MINIMUM_OPENCODE_VERSION = 2.1.0`）。
- 2.1.x 里 2.1.4 是唯一带完整 patch 轮的版本（2.1.0 → 2.1.4 四天四版），比 2.1.3 更晚收敛。
- 已知：OpenCode v2 **没有公开 changelog**（GitHub releases 只覆盖 1.x），所以 v2 的"更新记录"只能靠官方文档页 + `https://opencode.ai/config.json` 的 schema 差异推断。

### OpenChamber `2.5.1`

- 2.5.2 移除了侧边栏 Tree 视图（[hold 记录](#hold-刻意不升级)）。
- 2.5.1 是**最后一个在 UI 里提供 Tree / List 切换**的版本：它的 `dist` 里仍有切换菜单项（`viewMode.projects` / `viewMode.timeline`，取值 `sidebarViewMode` = `projects` / `timeline`）。2.5.2 的 `dist` 里 `sidebarViewMode` 只剩 6 处、全部是迁移 / 归一化读取，菜单已无切换项。
- `--host` / `--ui-password` / `OPENCHAMBER_DATA_DIR` / `OPENCODE_PORT` 在 2.5.1 的 `bin/lib/cli-args.js` 里都存在，`entrypoint.sh` 的启动参数不需要改。

### magic-context `0.49.21`

版本下限由三件事决定：

1. `0.49.17` 是**第一个支持 OpenCode 2.1.x** 的版本（我们在 2.1.4）。
2. `0.49.21` 修了 OpenCode 2 的消息检索，以及"回复里只含一个被复制的 tag"时向**严格 openai-compatible provider**（我们的 `commandcode`）发送空 part 被拒的问题；同时带上 Zod 4.6.7 的安全修复。
3. `0.49.22` / `0.49.23` 用 compare API 核对过：30 个文件全部落在 `packages/pi-plugin`（Pi / Oh My Pi），`packages/plugin` 只改了 `version` 字段 —— 对我们**等价**，但 soak 更短，所以选 0.49.21。

配置用 `v0.49.21` tag 的 `assets/magic-context.schema.json` 校验：0 error、0 deprecated key。

## 关键捆绑细节

- **opencode 版本真正生效的是 Dockerfile 那行**：`install-tools.sh` 只在二进制缺失时才装，所以两处必须同 commit 改。
- **magic-context 写死精确版本**，不用 `@latest`；`entrypoint.sh` 启动时会删掉所有**非当前 spec** 的插件缓存，避免长跑容器继续用旧构建。
- **`compaction` 有两个开关分属两个文件**：`opencode.jsonc` 的 `compaction.auto: false`（关 opencode 原生压缩）+ `magic-context.jsonc` 的 `compaction.enabled: true`（由 MC 独占窗口）。两者都不动。
- **`update: "notify"`**：保留提示，但不开自动安装。
