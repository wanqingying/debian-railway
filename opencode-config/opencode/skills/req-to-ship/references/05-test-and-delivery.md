# 阶段 5 — 自测联调与交付

**目标**：完成自测联调，交付上线。上线动作（提交+push+创建 MR）只在用户表达完成/上线/发布意图后执行。

## 动作步骤

### 1. 再次同步远程主分支代码
- `git fetch` 并确认分支与远程主分支同步，必要时 rebase/merge。
- 同步后：**执行 `codegraph sync`**。

### 2. 执行单测 + e2e 测试
- 运行方案阶段设计、实现阶段写好的全部单测与 e2e 测试。
- 结果全部通过才算自测完成；失败则修复后重跑。

### 3. 联调验证
- 如有必要，要求用户执行本地调试：给出**详细的调试步骤**（引用 `ops/debug-guides.md`）。
- 引导用户按 `launch-checklist.md` 核对上线前置条件（环境变量、数据库、第三方平台操作）。

### 4. 交付（受控动作）
**没有用户明确指令，禁止 push 代码。**
- 用户表达"完成开发、上线、发布"等意图后：
  1. 再次同步远程主分支代码（`git fetch` + 确认同步）。
  2. 提交所有变更（含文档：需求、方案、review、checklist、进度追踪——与代码同 commit 链）。
  3. `git push` 需求分支。
  4. **创建 MR**：提供 MR 描述（需求摘要、改动概览、测试结果、上线 checklist 状态、review 结论链接）。

## 注意事项
- push/MR 是受控动作，未获明确指令不得执行。
- 文档与代码一起交付，保证可追溯（review.md 记录、进度追踪、checklist 状态）。
- MR 描述要自包含：审查者不看会话也能理解改动。
